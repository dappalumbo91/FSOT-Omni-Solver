# LOCK9A (locked9a) — ablation of the LOCK7/7.1 changes (diagnostic lock, ideal 27 C only)

Locked 2026-10-15, before any LOCK9A simulation. Purpose (Damian, 8:21 PM): find why the LOCK7/7.1 ideal errors are 3–5x LOCK5's, one change at
a time. New forks: phase3/cpp/leafc9.cpp (from leafc8b.cpp, unchanged; built with detmath.cpp), phase3/cpp/netgen8.cpp (from netgen7.cpp,
unchanged; adds mode leafc9). No FSOT rule or value changes; each switch restores the LOCK5 form of one LOCK7/7.1 compiler change.

Variants (env FSOT_L9_ABL of leafc9; base engine LOCK7 via netgen8 unless noted):
- v71: no switch (= locked8b, the 7.1/8.1 compiler).
- flip: signal LOGRs in the LOCK5 orientation (signal on transdiode c1 at IIN, reference on cascoded c2 at IIN e^-3, t = -1).
- abs: no antilog input absorption (I_in = IIN).
- flipabs: flip + abs.
- base: constant-generator base cells at m c >= 1.4 (LOCK5) instead of >= e.
- early: no Early correction on uncascoded antilog inputs.
- rho: no range sizing.
- all: flip, abs, base, early, rho (the LOCK5 compiler forms on the 8.1 code base).
- v71_b6, all_b6: the v71 / all recipes run on the LOCK6 base engine (netgen5, design2 base: KD, PTAT ratio 16, unmatched PTAT pair, no
  R_ldi Early correction): isolates the base-engine changes (deeper LOGR baseline, ln 256 reference).
E-series snapping does not enter: the ideal_ideal variant uses the ideal resistor values (netgen Var e24 = false).
Runs: tools/run_bs9a.sh <variant> <key>, ideal_ideal, 27 C; keys GEN T1 2_M 2_P 2_T 2_X 2a_M 2a_P 2a_T 2a_X.
